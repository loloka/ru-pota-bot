# Техническая спецификация: Telegram-бот RU-POTA

## 1. Общее описание
Многофункциональный Telegram-бот для радиолюбительского сообщества POTA (Parks on the Air) на Node.js. 
Работает с двумя сущностями в Telegram:
- **Main Chat (Закрытая группа):** Общение, модерация, верификация позывных, команды.
- **Activity Channel (@pota_activity):** Канал/группа для трансляции спотов (только чтение для обычных пользователей).

## 2. Стек технологий
- Node.js (ES6 Modules, `"type": "module"`)
- Telegraf.js v4+ (с поддержкой Scenes/Wizards для анкет)
- better-sqlite3 (локальная SQLite БД в WAL-режиме)
- Axios (HTTP-клиент для работы с API POTA)
- dotenv (управление конфигурацией через переменные окружения)

## 3. Архитектура и переменные окружения (.env)
- `BOT_TOKEN` — токен Telegram-бота от @BotFather.
- `MAIN_CHAT_ID` — ID основного закрытого чата.
- `ACTIVITY_CHANNEL_ID` — ID канала/группы pota_activity.
- `POTA_API_BASE_URL` — https://api.pota.app (или next.pota.app)
- `POLL_INTERVAL_MS` — интервал опроса кластера (по умолчанию 60000-120000 мс).
- `ALLOWED_PREFIXES` — список префиксов парков для фильтрации глобального кластера (например, "RU-,BY-,KZ-").

## 4. Ключевой функционал

### 4.1. Разделение логики по чатам (Middleware)
- Бот игнорирует любые текстовые команды, если они присланы из `ACTIVITY_CHANNEL_ID`.
- В `MAIN_CHAT_ID` бот слушает команды, модерирует вход, принимает споты от верифицированных участников и общается с юзерами.
- В ЛС боту доступны персональные команды, анкета спота и справка.
- Трансляция спотов (кластер) направляется строго в `ACTIVITY_CHANNEL_ID`.

### 4.2. Система авторизации (Gatekeeper) в Main Chat
- Новые пользователи при входе получают `restricted`-права (read-only / запрет отправки сообщений).
- Для разблокировки пользователь отправляет команду `/callsign [ПОЗЫВНОЙ]`.
- Бот валидирует позывной, записывает связку `telegram_id` <-> `callsign` в SQLite и снимает ограничения в чате.

### 4.3. Автоматический опрос официального кластера POTA
- Фоновый воркер (`src/services/cluster.js`) периодически опрашивает API POTA.
- Фильтрация по региону (ГЕО-фильтр): бот проверяет поле референса в каждом полученном споте. В канал `ACTIVITY_CHANNEL_ID` отправляются ТОЛЬКО те споты, референс которых начинается с одного из префиксов, указанных в `ALLOWED_PREFIXES` (например, только `RU-`) .
- Дедупликация: сохраняет ID уже отправленных спотов в БД/памяти, чтобы не спамить дубликатами при каждом опросе API.

### 4.4. Локальный споттер (Отправка спота пользователями)
- Споты могут отправлять только пользователи с зарегистрированным позывным из `MAIN_CHAT` или в ЛС боту.
- **Два режима отправки:**
  1. Быстрый: `/spot <ТЕКСТ>`
  2. Интерактивная анкета / Wizard (кнопки или пошаговый диалог):
     - Статус: *СЕЙЧАС НА СВЯЗИ* или *ПЛАНИРУЮ*
     - Позывной (по умолчанию подставляется зарегистрированный, напр. `R2BBX/p`)
     - Частота / Диапазон (напр. `7.125 MHz` / `40m`)
     - Референция POTA (напр. `RU-0073`) и название (напр. `Парк Сокольники`)
     - RDA район (напр. `MA-01` или двойной `NS-03/NS-04`)
     - Модуляция (MODE: `CW`, `SSB`, `CW+SSB`, `FT8` и т.д.)
     - Мощность (PWR: `100W`, `5W QRP` и т.д.)
     - Комментарий / Антенна (COMMENT: `end-fed-40m`, `inv-v` и т.д.)
- **Результат:** Формируется красивое оформленное сообщение (напр. `📅 28.08.2026 📻 R2BBX/p 🏞️ RU-0073 Парк Сокольники (RDA MA-01/MA-05) | CW+SSB | 90W | end-fed-40m`) и отправляется в `ACTIVITY_CHANNEL_ID`.
- Перспектива: отправка спота в официальный API POTA при согласовании доступа/эндпоинта.

### 4.5. Справочные команды (Main Chat и ЛС)
- `/stats [позывной]` — статистика активатора/охотника из API POTA.
- `/park [референс]` — подробная информация по парку (название, локация, статус ATNO).
- `/sub [позывной]` — подписка на уведомление о появлении конкретного позывного в кластере.

### 4.6. Модерация в Main Chat
- `/ban`, `/mute` (реплай на сообщение нарушителя) — доступно только администраторам.
- Автоматическое удаление сервисных системных сообщений Telegram ("Пользователь вступил в группу").
